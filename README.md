# 工作台提示词助手

面向没有产品设计和开发经验的用户，把一句“我想做一个工作台”的模糊想法，整理成结构完整、可执行、可验收的工作台搭建提示词。

项目采用中文优先的表达方式，支持从一句话开始，通过多轮需求访谈完成目标澄清、范围取舍、流程建模、方案验证和提示词输出。

## 项目简介

工作台提示词助手围绕以下问题展开需求整理

- 工作台服务谁
- 主要解决什么问题
- 用户在什么场景下使用
- 第一阶段需要完成什么任务
- 页面如何组织
- 数据如何记录和流转
- 不同角色能够查看和操作什么
- 异常情况如何处理
- 是否依赖外部数据或系统
- 如何判断方案已经达到可用标准

最终产出一份可以提交给工作台搭建师的完整提示词。

## 核心能力

### 低门槛需求访谈

支持从一句话开始，不要求用户预先掌握产品设计、数据库、接口或权限知识。每轮只围绕一个主题提问，并结合上下文提供可选方向。

### 结构化提问优先

工作台类型、功能方向、用户角色、视觉风格、第一阶段范围和需求冲突等选择类问题，优先使用宿主环境提供的结构化提问组件。

宿主环境缺少结构化提问能力时，自动使用文字选项。用户可以回复序号，也可以直接补充自己的想法。

### 需求台账

持续区分以下内容

- 已确认需求
- 建议值
- 待确认事项
- 用户约束
- 冲突需求
- 高风险事项
- 当前优先级
- 信息来源

### 第一阶段范围控制

将需求划分为核心闭环、效率增强、后续扩展和暂缓内容，帮助用户先完成最重要的业务任务，减少初版范围失控带来的返工。

### 方案验证

生成最终提示词前，通过典型场景模拟检查页面、流程、数据、权限和反馈是否能够连贯工作，并生成可执行的验收标准。

### 搭建后的持续优化

用户完成初次搭建后，可以继续提供使用问题或搭建结果。助手会识别目标、页面、流程、数据、权限、视觉和外部依赖方面的问题，并生成修订版提示词。

## 适用场景

- 客户经营工作台
- 任务协作工作台
- 流程审批工作台
- 数据看板
- 内容管理工作台
- 知识库和资料管理工作台
- 表单收集工作台
- 运营管理工作台
- 自定义业务工作台

## 安装

### 方式一：使用 Git 克隆

适合需要持续更新和参与维护的用户。

```bash
git clone https://github.com/wangchentalk/workbench-prompt-assistant.git ~/.workbuddy/skills/workbench-prompt-assistant
```

Windows 用户可以在 PowerShell 中执行

```powershell
git clone https://github.com/wangchentalk/workbench-prompt-assistant.git "$env:USERPROFILE\.workbuddy\skills\workbench-prompt-assistant"
```

### 方式二：下载 ZIP 压缩包

1. 打开 GitHub 仓库页面。
2. 点击 `Code`。
3. 选择 `Download ZIP`。
4. 解压后，将 `workbench-prompt-assistant` 文件夹复制到用户级 Skill 目录。
5. 确认文件夹内直接包含 `SKILL.md`、`README.md`、`references` 和 `tests`。

用户级 Skill 目录通常为

```text
Windows
%USERPROFILE%\.workbuddy\skills\workbench-prompt-assistant\

macOS 或 Linux
~/.workbuddy/skills/workbench-prompt-assistant/
```

安装完成后，刷新 Skill 列表或重新启动 WorkBuddy。确认 Skill 列表中出现“工作台提示词助手”后即可开始使用。

### 安装检查

确认以下文件存在

```text
workbench-prompt-assistant/
├── SKILL.md
├── README.md
├── references/
└── tests/
```

### 启动对话

直接输入一句话即可

```text
我想做一个工作台。
```

也可以补充业务背景

```text
我想让销售每天看到需要跟进的客户，并记录沟通结果。
```

助手会先确认工作台目标，再逐步整理用户、场景、功能、页面和流程。

### 选择推荐方向

宿主环境支持结构化选项时，可以直接点击单选或多选项。

如果当前环境使用文字选项，可以回复序号

```text
选择 1 和 3，权限请按常见做法推荐。
```

也可以直接用自然语言补充其他方案。

### 处理不确定内容

遇到暂时无法判断的专业问题，可以回复

```text
请你推荐
```

或

```text
我不确定，按常见做法设计。
```

助手会给出符合场景的建议值，并在最终方案中单独标记，方便后续确认。

### 获取最终方案

需求达到生成门槛后，输出以下内容

1. 一句话定位
2. 需求理解摘要
3. 已确认需求
4. 建议值
5. 第一阶段核心方案
6. 后续扩展方案
7. 页面与模块
8. 核心业务流程
9. 数据结构与关系
10. 角色、权限与协作
11. 异常与边界场景
12. 外部依赖与实现边界
13. 视觉与交互方向
14. 典型场景模拟
15. 验收标准
16. 待确认事项与风险
17. 可直接复制的完整搭建提示词

## 推荐的首次输入

```text
我想制作一个客户管理工作台，主要给销售团队使用，希望解决客户资料分散、跟进不及时的问题。请先通过提问帮我整理需求，不确定的地方请给我推荐选项。
```

## 参考文档

- `SKILL.md` 记录核心角色、触发条件、状态机、交互规则和输出契约。
- `references/interaction-protocol.md` 记录结构化提问、文字兜底、状态转移、冲突处理和终止条件。
- `references/workbench-types.md` 记录工作台类型识别和类型化追问重点。

## 交互组件说明

选择界面是否呈现为弹窗、按钮或选择卡片，取决于宿主环境提供的交互能力。

本项目保留两条交互路径

```text
宿主支持结构化提问
→ 优先调用原生选择组件
→ 用户完成选择后继续对话

宿主缺少结构化提问能力
→ 使用文字选项
→ 用户回复序号或自然语言
→ 继续完成需求访谈
```

项目不会虚构已经显示的界面，也不会把宿主环境尚未提供的能力写成确定结果。

## 设计边界

- 负责需求分析和提示词生成，不直接完成工作台搭建。
- 保持通用平台视角，用户明确指定平台时再纳入平台约束。
- 不虚构接口、账号、权限、数据源或连接状态。
- 低优先级内容可以采用建议值，并在输出中单独标记。
- 影响整体架构的内容需要保留在待确认事项中。
- 涉及敏感数据时，需要明确数据范围、访问权限、操作日志和恢复机制。

## 测试

测试用例位于 `tests/test-cases.md`，覆盖以下场景

- 一句话模糊输入
- 结构化提问优先
- 结构化提问不可用时的文字兜底
- 用户请求推荐
- 暂时跳过专业问题
- 功能过多与第一阶段范围取舍
- 前后回答冲突
- 外部系统依赖不明确
- 数据对象关系缺失
- 立即生成和二次优化
