# 工作台提示词助手

面向没有产品设计或开发经验的用户，将一句“我想做一个工作台”的模糊想法，整理为结构完整、可执行、可验收的工作台搭建提示词。

> 中文优先。详细规则、对话示例和验收清单见 `references/` 目录。

## 项目简介

工作台提示词助手采用多轮需求访谈方式，帮助用户逐步明确：

- 工作台服务对象与核心问题
- 典型使用场景和核心业务闭环
- 第一阶段功能与后续扩展范围
- 页面结构和用户操作路径
- 数据对象、字段和关联关系
- 用户角色、数据范围和操作权限
- 异常处理、通知、审批与协作机制
- 外部数据源、系统连接和实现依赖
- 视觉风格、交互反馈和响应式要求
- 可观察、可操作、可验证的验收标准

最终输出一份可直接交给工作台搭建师使用的完整提示词。

## 核心能力

### 小白友好的需求访谈

支持从一句话开始，不要求用户预先掌握产品设计、数据库、接口或权限知识。每轮只追问一个主题，并根据当前回答提供上下文相关的选项。

### 结构化提问优先

对于工作台类型、功能方向、角色、视觉风格、MVP 范围和需求冲突等选择类问题，优先使用宿主环境提供的结构化提问组件。

如果宿主环境不支持结构化提问，则自动退化为文字选项。文字模式支持用户回复序号，也支持自由描述，不会中断问答流程。

### 需求台账与状态管理

持续区分以下内容：

- 已确认需求
- 建议值
- 待确认事项
- 用户约束
- 冲突需求
- 高风险事项
- 当前优先级
- 信息来源

### MVP 范围控制

将需求分为核心闭环、效率增强、后续扩展和暂不纳入，避免第一版功能过多，导致页面、流程、数据和权限相互失配。

### 方案验证

在生成最终提示词前，通过典型场景模拟检查页面、流程、数据、权限和反馈是否能够连贯工作，并生成验收标准。

### 二次优化

用户完成初次搭建后，可以继续提供搭建结果或使用问题，助手会区分目标、页面、流程、数据、权限、视觉和外部依赖问题，生成修订版提示词。

## 适用场景

- 客户经营工作台
- 任务协作工作台
- 流程审批工作台
- 数据看板
- 内容管理工作台
- 知识库或资料管理工作台
- 表单收集工作台
- 运营管理工作台
- 其他自定义业务工作台

## 使用方式

### 1. 启动对话

可以直接输入：

```text
我想做一个工作台。
```

也可以给出更具体的描述：

```text
我想让销售每天看到需要跟进的客户，并记录沟通结果。
```

助手会先确认工作台目标，再逐步询问用户、场景、功能和流程。

### 2. 对选项进行选择

遇到结构化选项时，直接点击单选或多选项即可。

如果当前环境以文字形式呈现选项，可以回复序号，例如：

```text
选择 1 和 3，权限请你按常见做法推荐。
```

也可以直接用自然语言补充自己的方案。

### 3. 处理不确定内容

无法回答专业问题时，可以回复：

```text
请你推荐
```

或：

```text
我不确定，按常见做法设计
```

助手会采用符合场景的建议值，并在最终方案中明确标注，避免把推断内容误写成已确认需求。

### 4. 获取最终方案

需求达到完整性门槛后，助手会输出：

1. 一句话定位
2. 需求理解摘要
3. 已确认需求
4. 建议值
5. 第一阶段核心方案
6. 后续扩展方案
7. 页面与模块
8. 核心业务流程
9. 数据结构与关系
10. 角色、权限与协作
11. 异常与边界场景
12. 外部依赖与实现边界
13. 视觉与交互方向
14. 典型场景模拟
15. 验收标准
16. 待确认事项与风险
17. 可直接复制的完整搭建提示词

## 推荐的首次输入

```text
我想制作一个客户管理工作台，主要给销售团队使用，希望解决客户资料分散、跟进不及时的问题。请先通过提问帮我整理需求，不确定的地方请给我推荐选项。
```

## 交互组件说明

结构化提问是否呈现为弹窗、按钮或选择卡片，取决于当前宿主环境是否提供对应的交互组件。

本 Skill 采用双路径设计：

```text
宿主支持结构化提问
→ 优先调用原生选择组件
→ 用户点击后继续对话

宿主不支持结构化提问
→ 使用文字选项
→ 用户回复序号或自然语言
→ 继续完成需求访谈
```

Skill 不会虚构已经显示弹窗，也不会把宿主环境未提供的界面能力写成确定结果。

## 设计边界

- 不直接完成工作台搭建，只负责需求分析和提示词生成。
- 不绑定某一个应用搭建平台，除非用户明确指定。
- 不虚构接口、账号、权限、数据源或连接状态。
- 对未确认的低优先级内容可以提出建议值。
- 对会改变整体架构的内容保留待确认事项。
- 涉及敏感数据时，需要明确数据范围、访问权限、日志和恢复机制。

## 测试

测试用例位于 `tests/test-cases.md`，覆盖：

- 一句话模糊输入
- 结构化提问优先
- 宿主不支持时文字兜底
- 用户请求推荐
- 暂时跳过专业问题
- 功能过多与 MVP 取舍
- 前后回答冲突
- 外部系统依赖不明确
- 数据对象关系缺失
- 立即生成和二次优化
