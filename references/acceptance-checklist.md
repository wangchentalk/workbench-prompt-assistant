# 验收清单

## 一、生成前检查

### 目标与范围

- [ ] 能用一句话说明服务对象、主要问题和期望结果
- [ ] 至少有一个典型使用场景
- [ ] 第一阶段范围可以在一个核心闭环内完成
- [ ] 已区分核心功能、效率增强、后续扩展和暂不纳入

### 页面与流程

- [ ] 有明确入口页面
- [ ] 每个核心任务都有对应页面或操作
- [ ] 页面之间存在连续的进入和返回关系
- [ ] 流程有开始条件、关键步骤和结束结果
- [ ] 至少考虑一个异常或边界场景

### 数据与权限

- [ ] 核心数据对象已经列出
- [ ] 关键字段足以支撑核心流程
- [ ] 数据对象之间的关系清晰
- [ ] 角色与数据查看范围明确
- [ ] 创建、编辑、审核、分配、删除等权限有基本规则

### 依赖与风险

- [ ] 已明确数据源或记录“暂无外部依赖”
- [ ] 外部系统的账号、授权和同步规则没有被虚构
- [ ] 重大冲突已经解决或列入待确认事项
- [ ] 建议值没有混入已确认需求

## 二、典型场景模拟

对最重要的一条路径逐步检查：

- [ ] 用户知道从哪里开始
- [ ] 每一步都有对应页面或动作
- [ ] 每一步所需数据都已经存在
- [ ] 当前角色拥有完成该步骤的权限
- [ ] 系统反馈足以让用户知道发生了什么
- [ ] 目标结果可以被查看、保存或统计
- [ ] 失败时不会产生无法恢复的错误状态

## 三、输出前检查

- [ ] 一句话定位准确
- [ ] 已确认需求、建议值和待确认事项分区清晰
- [ ] 第一阶段方案完整
- [ ] 后续扩展没有挤占核心范围
- [ ] 页面、流程、数据、权限相互匹配
- [ ] 有至少三条具体验收标准
- [ ] 完整提示词可以直接复制
- [ ] 提示词使用明确动作和条件，不使用空泛形容词
- [ ] 已写出实现依赖和潜在风险
- [ ] 已包含工作台搭建师交接提醒

## 四、交给搭建师后的验收

### 核心功能

- [ ] 用户可以完成第一阶段核心任务
- [ ] 核心数据可以新增、查看和按需要修改
- [ ] 页面操作顺序符合方案

### 数据与权限

- [ ] 数据对象和字段与方案一致
- [ ] 角色只能看到允许的数据
- [ ] 无权限操作会被阻止并得到明确反馈
- [ ] 关键操作有日志或可追溯记录，若不需要则明确说明

### 异常处理

- [ ] 错误输入有提示
- [ ] 重复提交有处理
- [ ] 删除或重要变更有确认机制
- [ ] 同步失败或网络异常有反馈
- [ ] 逾期、退回、撤回等状态符合方案

### 交互体验

- [ ] 用户能从首页找到核心任务入口
- [ ] 加载、空数据、成功和失败状态清晰
- [ ] 移动端或桌面端适配符合已确认要求
- [ ] 用户完成任务后能看到明确结果

## 五、质量判断

若任何一项核心闭环、数据关系、权限范围或重大依赖未明确，不输出“已完成”的表述。可以输出“可交给搭建师的第一版方案”，并把缺口写入待确认事项。
