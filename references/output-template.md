# 方案与提示词输出模板

## 一句话定位

`这是一个服务于【目标用户】、帮助其完成【核心任务】并解决【主要问题】的【工作台类型】。`

## 需求理解摘要

用三至五句话说明目标、场景、核心结果和第一阶段范围。

## 已确认需求

只写用户已经明确表达并确认的内容。

- 目标用户
- 主要问题
- 核心场景
- 第一阶段目标
- 必须实现的功能
- 主要页面
- 核心角色
- 明确约束

## 建议值

写出助手根据常见场景补充的内容，并注明采用理由。建议值不得伪装成用户确认内容。

- 建议页面结构
- 建议数据字段
- 建议权限方式
- 建议异常处理
- 建议视觉方向

## 第一阶段核心方案

围绕一个核心业务闭环说明：

1. 用户从哪里进入
2. 用户完成什么操作
3. 系统保存或处理什么数据
4. 用户如何看到结果
5. 下一步动作是什么

## 后续扩展方案

列出暂不影响核心闭环的增强功能，并说明放入后续版本的原因。

| 角色 | 可查看范围 | 可创建或编辑 | 可审核或分配 | 其他限制 |
|---|---|---|---|---|
|  |  |  |  |  |

同时说明通知、评论、提醒、审批、日志和导出规则。

## 异常与边界场景

列出重复数据、错误输入、逾期、退回、撤回、删除恢复、同步失败、无权限和提交失败等适用项。不适用的项写明“本阶段暂不处理”。

## 外部依赖与实现边界

说明数据源、外部系统、账号权限、同步方向、同步频率、授权条件和失败处理。未确认的内容写入待确认事项，不做能力承诺。

## 视觉与交互方向

说明界面风格、信息层级、布局、颜色倾向、关键组件、空状态、加载状态、成功反馈、错误反馈和响应式适配。

## 典型场景模拟

用以下格式展示一条完整路径：

`角色 → 入口 → 操作一 → 操作二 → 系统反馈 → 目标结果`

补充模拟中发现的缺口和修正动作。

## 验收标准

使用可观察、可操作、可验证的描述：

- 给定某个初始条件，用户可以完成某项操作
- 完成后某条数据会出现明确变化
- 指定角色只能看到允许的数据
- 错误输入会得到清晰提示，数据不会被错误保存
- 核心流程可以从入口页面走到目标结果

## 待确认事项与风险

只列出会影响整体架构、权限、数据安全、外部依赖或核心流程的问题。每项说明影响。

## 可提交给工作台搭建师的完整提示词

```text
请制作一个工作台，要求优先完成第一阶段核心业务闭环，并为后续扩展保留合理空间。

一、工作台定位
服务对象：【填写已确认内容】
解决问题：【填写已确认内容】
核心结果：【填写已确认内容】

二、目标用户与角色
【填写角色、职责、查看范围和操作权限】

三、核心使用场景
【填写最典型场景和使用频率】

四、第一阶段必须实现的功能
【按优先级列出功能，并说明每项功能对应的用户任务】

五、页面与模块
【逐一说明页面目标、主要内容、关键操作、入口和去向】

六、核心业务流程
【描述开始条件、关键步骤、系统反馈、结束结果和异常处理】

七、数据结构
【说明数据对象、字段、来源、对象关系和读写规则】

八、权限与协作
【说明角色权限、数据范围、通知、评论、提醒、审批和日志】

九、外部依赖与实现边界
【说明连接系统、数据源、授权条件、同步规则和待确认依赖】

十、视觉与交互
【说明风格、布局、组件、空状态、加载、成功、失败和响应式要求】

十一、验收标准
【列出可观察、可操作、可验证的验收标准】

十二、建议值与待确认事项
【明确区分助手建议和会影响实现的未决问题】

请先完成核心业务闭环，再考虑后续扩展。不要虚构未提供的数据、权限、外部连接或已完成状态。对于未明确的低优先级内容，采用合理建议并标记为建议值。对于会影响整体架构的内容，保留待确认事项并在搭建前提示确认。
```
